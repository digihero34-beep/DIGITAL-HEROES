# Digital Heroes — System Risk Register & Mitigation Strategy

> **Document Type**: Exhaustive Risk Register & Proactive Mitigation Matrix  
> **Rule Compliance**: Master Engineering Prompt Task 19 ("Risk Analysis")  
> **Severity Levels**: Critical, High, Medium, Low  

---

## 1. Risk Evaluation Framework

Risks are categorized across all technical and product dimensions of the Digital Heroes platform. Each entry identifies the potential failure mode, evaluates probability and impact, establishes architectural mitigations, and defines the verification protocol.

---

## 2. Exhaustive Risk Register

| Risk ID | Category | Description | Likelihood | Impact | Severity | Proactive Mitigation Strategy | Verification Protocol | Owner / Domain |
| :--- | :--- | :--- | :---: | :---: | :---: | :--- | :--- | :--- |
| **RSK-01** | **Payment** | Stripe webhook failure or out-of-order delivery causes subscriber state desynchronization. | Medium | High | **High** | Implement persistent webhook ledger (`stripe_webhook_events`) with event timestamp ordering and idempotent handlers. Fall back to real-time Stripe API check on dashboard load if status is ambiguous. | Webhook replay integration test; simulated failed webhook delivery test. | Subscriptions & Billing |
| **RSK-02** | **Draw / Game** | Algorithmic draw mode produces non-uniform edge cases or crashes on empty score set. | Low | Critical | **High** | Laplace (+1) smoothing guarantees non-zero probability for every number 1–45 even if zero scores have been entered. Strict validation requires active subscriber count > 0 before draw publication. | Unit tests running 100,000 simulated draws with skewed distributions. | Draw Engine |
| **RSK-03** | **Data Integrity** | Race condition allows user to insert two scores with identical dates or exceed 5 active scores. | Medium | High | **High** | Database-level `UNIQUE(user_id, played_date)` constraint and atomic trigger `trg_maintain_rolling_five_scores` enforce invariants independent of application layer. | Concurrent parallel HTTP submission tests with identical payloads. | Golf Scores |
| **RSK-04** | **Security** | Insecure Direct Object Reference (IDOR) allows Subscriber A to view or claim Subscriber B's prize. | Medium | Critical | **Critical** | Server-side authorization checks `auth.uid() = user_id` on all winner/payout queries. Supabase RLS enforces data isolation at the database engine layer. | Automated security test asserting 403 Forbidden when requesting another user's claim ID. | Security & Winners |
| **RSK-05** | **Financial** | Multi-winner prize split incurs rounding errors, creating or destroying currency. | High | Medium | **Medium** | All monetary math executed in integer smallest currency units (cents/pence). Exact division remainder $R = \text{Pool} \pmod N$ distributed 1 penny each to first $R$ winners. | Unit test for £100 split across 3 winners verifies sum identically equals 10000 cents. | Prize Pools |
| **RSK-06** | **Security** | Malicious executable file uploaded to winner verification storage. | Medium | Critical | **Critical** | File upload pipeline validates magic bytes/signatures, enforces whitelist of MIME types (`image/png`, `image/jpeg`, `application/pdf`), and 10MB limit. Stored in private bucket with random UUID names. | Attempt to upload renamed `.exe` and `.sh` files; verify rejection. | Winners & Storage |
| **RSK-07** | **UX / Brand** | Interface resembles generic gambling/casino platform or traditional golf country-club. | High | High | **High** | Enforce "Feel, not fairway" design system tokens. Eliminate casino tropes (no slots, no spinning wheels). Editorial dark canvas with electric mint impact accents leads with charity. | Design review by product design lead prior to phase sign-off. | UI / UX Design |
| **RSK-08** | **Accessibility** | Interactive scorecard and draw ball animations fail WCAG 2.1 AA or cause vestibular distress. | Medium | High | **Medium** | Wrap all animations in `@media (prefers-reduced-motion: reduce)`. Enforce minimum 4.5:1 text contrast ratios. Full keyboard navigation and ARIA live regions for draw reveals. | Automated Axe-core accessibility audit and manual keyboard tab navigation review. | UI / UX Design |
| **RSK-09** | **Product Scope** | Missing PRD Page 11 (§ 13 Technical & § 14 Scalability) creates architectural ambiguity. | High | Medium | **Medium** | All omitted technical requirements derived directly from PRD § 15 Mandatory Deliverables and the 22 Industrial Architecture and Database rules. Cataloged in `docs/ASSUMPTIONS.md`. | Review against PRD Table of Contents and Deliverables checklist. | Architecture Lead |
| **RSK-10** | **Operations** | Admin publishes draw accidentally or before verification of simulated results. | Low | Critical | **High** | Draw publication requires two-step confirmation modal with explicit text typing ("PUBLISH"). Database check constraint prevents re-publishing or modifying published draw numbers. | E2E Playwright test verifying publish confirmation barrier. | Administration |
| **RSK-11** | **Performance** | Draw matching query against large subscriber base causes database timeout or N+1 queries. | Medium | High | **Medium** | Draw matching uses PostgreSQL array set intersection (`&&`) over indexed score arrays, executing set matching in a single query under 200ms. | Database benchmark test matching 10,000 subscriber score sets against draw numbers. | Database Architecture |
| **RSK-12** | **Deployment** | Vercel production deployment fails due to mismatched environment variables or missing keys. | Medium | High | **High** | Maintain typed environment schema with Zod validation in `env.mjs`. Build process fails immediately at build time if any required variable is missing or malformed. | Execute `npm run build` with mocked production environment variables. | DevOps & Infrastructure |
| **RSK-13** | **Compliance** | Charity contribution fails to meet mandatory 10% statutory/PRD requirement. | Low | Critical | **Critical** | Database `CHECK (contribution_percentage >= 10)` constraint; UI slider has hard minimum floor at 10%; server Zod schema enforces `.min(10)`. | Unit test submitting 9% contribution fails at both API and database layers. | Charities Domain |
| **RSK-14** | **Payout State** | Payout marked as `Paid` before winner proof screenshot is officially reviewed and approved. | Low | Critical | **Critical** | Database foreign key and state machine guard prevent payout creation until `winners.verification_status === 'approved'`. Server action `markPayoutPaidAction` requires admin role and valid transaction reference. | Test attempting to transition unverified winner payout to paid returns `InvalidStateError`. | Payouts Domain |
